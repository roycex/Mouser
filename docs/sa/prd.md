## 1. 背景与目标

### 1.1 现状

Mouser 是 Logitech Options+ 的本地替代实现（Python 3.10+ / PySide6 QML）。其核心能力是**把罗技鼠标的任意可配置按键重映射为一个动作**。当前动作集有三种形态（`docs/preprocess/code-overview.md` §A.3）：

1. **静态按键组合**（如 `volume_mute`、`alt_tab`）
2. **参数化前缀动作**（`custom:<组合键>`，动作 id 自带数据）
3. **Engine 内部动作**（`switch_scroll_mode`、`cycle_dpi` 等）

全部动作都止步于「模拟输入」——**无法启动本机程序**。用户想让一个鼠标按键打开某个应用，目前只能绕道 `custom:` 去模拟 Win 键搜索或自建快捷方式，体验割裂。

### 1.2 目标

新增第四类动作：**启动程序动作**。用户注册一个「启动目标」（程序路径 + 启动参数 + 工作目录），把它绑定到任意鼠标按键；按下按键即启动该程序。

**成功判据（可观测）**：
- 用户能把一个已注册目标绑定到任意可配置按钮，绑定关系在 UI 中显示为目标名称
- 按下该按钮，目标程序按配置的参数与工作目录启动
- 重启 Mouser 后注册表与绑定完整保留；旧版本 config 无损升级
- 启动动作不阻塞鼠标 Hook 线程（按键后鼠标立即恢复响应）

### 1.3 范围

**IN**
- 启动目标注册表（增 / 改 / 删 / 浏览选择）
- 启动参数与工作目录
- 动作选择器中的选择入口与目标展示
- 按钮绑定（含手势滑动方向与 tap 动作）
- 异步启动执行 + 失败状态提示
- config 版本迁移
- 简体 / 繁体中文翻译

**OUT（明确不做）**
- 打开文档 / 文件夹（`os.startfile` 语义）
- 用默认浏览器打开 URL
- 管理员权限提权运行（Windows UAC / `ShellExecute runas`）
- 进程去重、窗口激活 / 前台切换
- 环境变量展开（`${HOME}` / `%USERPROFILE%`）与 `~` 展开
- `.lnk` 快捷方式、`.bat` / `.cmd` 脚本的启动

## 3. 功能清单（F-XXX）

| 功能编号 | 功能名称 | 描述 | 关联需求 | 优先级 |
|---|---|---|---|---|
| F-001 | 启动目标注册表 | 在 `config.json` 的 `settings.launch_targets` 中持久化启动目标列表；每个目标含唯一 id、名称、程序路径、启动参数、工作目录 | R-001 R-002 R-003 R-005 R-014 | P0 |
| F-002 | 目标 CRUD 界面 | 提供模态对话框完成目标的浏览新增、编辑、删除、重命名；支持从已安装应用清单选择或手动浏览文件 | R-001 R-004 | P0 |
| F-003 | 启动动作 id 模型 | 动作 id 形如 `launch:<target_id>`；提供 id 编解码、标签解析、失效判定 | R-008 R-011 | P0 |
| F-004 | 选择器集成 | 动作选择器中新增「启动程序」分类，列出全部已注册目标作为可选动作，并提供一个「新增启动程序…」入口 | R-006 | P0 |
| F-005 | 按钮绑定 | 任一可配置按钮（含手势滑动方向、tap 动作、Actions Ring 槽位）均可绑定 `launch:<id>` 动作；绑定按 per-profile 语义落盘 | R-007 R-009 | P0 |
| F-006 | 异步启动执行 | 按键触发时把启动请求从 Hook 线程转出，在 Qt GUI 线程执行 `subprocess.Popen`，不阻塞鼠标 | R-010 R-020 | P0 |
| F-007 | 参数与工作目录应用 | 启动时实际应用已配置的参数列表与工作目录；工作目录留空时使用程序自身所在目录 | R-011 | P0 |
| F-008 | 失败反馈 | 路径不存在、工作目录不存在、权限不足、参数非法等情形通过 UI 状态提示反馈具体原因，不崩溃、不静默 | R-012 R-019 | P1 |
| F-009 | 配置迁移 | `config.json` 版本 11 → 12；旧配置加载后行为不变、无报错；新键默认类型正确 | R-015 R-021 | P0 |
| F-010 | 失效目标降级 | 删除目标时解除引用它的按钮绑定并提示；对残留的失效 `launch:` id，UI 与执行侧均优雅降级 | R-016 | P1 |
| F-011 | 国际化 | 新增分类标签、对话框文案、状态提示提供 `zh_CN` 与 `zh_TW` 翻译；用户自定义目标名不参与翻译 | R-017 | P1 |
| F-012 | 三平台一致性 | Windows 走 `.exe` 直接启动；macOS 对 `.app` 包走 LaunchServices；Linux 走解析后的可执行文件；三平台均有可执行代码路径 | R-018 | P0 |
| F-013 | 纯逻辑可测性 | 目标校验、参数分词、argv 构造、id 编解码等核心逻辑置于不依赖 Qt 的模块，可脱离 PySide6 单元测试 | R-022 | P1 |
| F-014 | 打包一致性 | 新增 Python 模块与 QML 文件不破坏三份 PyInstaller spec 守卫测试 | R-023 | P1 |

## 4. 验收标准（EARS）

### 4.1 事件驱动（Event-driven）

| 编号 | 验收标准 | 覆盖 |
|---|---|---|
| AC-001 | **When** 用户在选择器中点击某已注册目标，**the system shall** 把 `launch:<target_id>` 写入当前 profile 的对应按钮映射并落盘 | F-003 F-005 |
| AC-002 | **When** 用户按下已绑定启动动作的按钮，**the system shall** 在不阻塞 Hook 线程的前提下发起一次程序启动 | F-006 |
| AC-003 | **When** 启动请求被执行，**the system shall** 以列表参数形式传入程序路径与解析后的参数，并设置配置的工作目录，且 `shell=False` | F-007 R-019 |
| AC-004 | **When** 目标程序路径不存在，**the system shall** 通过状态栏提示明确原因，且不抛出未捕获异常 | F-008 |
| AC-005 | **When** 用户删除一个启动目标，**the system shall** 把所有引用该目标的按钮映射重置为 `none`，并提示解除了多少处绑定 | F-010 |
| AC-006 | **When** config 从版本 11 加载，**the system shall** 补齐 `settings.launch_targets` 与版本号，且不修改任何既有字段的值 | F-009 |

### 4.2 状态驱动（State-driven）

| 编号 | 验收标准 | 覆盖 |
|---|---|---|
| AC-007 | **While** 一个按钮的映射为 `launch:<id>`，**the system shall** 在 UI 中把该按钮的动作显示为目标名称 | F-003 |
| AC-008 | **While** 映射引用的目标已不存在，**the system shall** 在 UI 中不显示为已选中的正常动作，并在执行时给出「目标已失效」提示而非崩溃 | F-010 |
| AC-009 | **While** 用户未注册任何启动目标，**the system shall** 在选择器中仅显示「新增启动程序…」入口，不影响其他动作的显示与选择 | F-004 R-021 |
| AC-010 | **While** Mouser 运行在不支持的平台上，**the system shall** 保持既有 `execute_action` stub 行为，不引入新的导入错误 | F-012 |

### 4.3 非期望行为（Unwanted behaviour）

| 编号 | 验收标准 | 覆盖 |
|---|---|---|
| AC-011 | **If** 启动参数文本包含未闭合的引号，**then the system shall** 在保存时拒绝并给出内联错误提示，不写入非法配置 | F-008 |
| AC-012 | **If** 目标工作目录不存在，**then the system shall** 拒绝保存该目标并提示，或在启动时明确报错 | F-008 |
| AC-013 | **If** 启动参数为空，**then the system shall** 正常启动该程序且不传入任何额外参数 | F-007 |
| AC-014 | **If** 同一目标被绑定到多个不同按钮，**then the system shall** 每个按钮触发时各自独立启动一次，互不影响 | R-013 |
| AC-015 | **If** 已注册目标的程序已在运行，**then the system shall** 不做去重、不做前台激活，再启动一个新实例 | R-013 |

### 4.4 通用（Ubiquitous）

| 编号 | 验收标准 | 覆盖 |
|---|---|---|
| AC-016 | The system shall 不修改任何既有动作 id 与语义，且不破坏现有 config 字段 | R-021 |
| AC-017 | The system shall 保证核心逻辑（id 编解码、目标校验、参数分词、argv 构造）可在不安装 PySide6 的环境中被导入与单元测试 | R-022 |
| AC-018 | The system shall 保证新增 QML 文件仅使用已映射到 Qt 库白名单的 QML import，使三份 PyInstaller spec 守卫测试通过 | R-023 |
| AC-019 | The system shall 为新增的分类标签与对话框文案提供 `zh_CN` 与 `zh_TW` 两套翻译，且用户自定义的目标名称原样显示 | F-011 |
| AC-020 | The system shall 保证新增的 4 个平台分支（win32 / darwin / linux / stub）中，支持平台的 `execute_action` 均能识别 `launch:` 动作 | F-012 |

## 6. 待确认决策（Design 阶段收敛，随设计评审一并确认）

| 编号 | 决策项 | 设计倾向 |
|---|---|---|
| D-01 | 启动目标 id 格式 | `t_<毫秒时间戳>_<4位随机>`，稳定且可读性够用 |
| D-02 | `launch:` 前缀 vs `custom:` 前缀复用 | 新前缀 `launch:`（`custom:` 的载荷是组合键，语义不同） |
| D-03 | 启动参数存储形态 | 存**原始文本字符串**，启动时按确定性规则分词；保存时校验合法性 |
| D-04 | 参数分词规则 | 自定义确定性分词器（反斜杠始终字面量），而非 `shlex`（避免 Windows 路径被 `\` 转义吞掉） |
| D-05 | 工作目录留空默认值 | 取**程序自身所在目录**（macOS `.app` 取包的父目录） |
| D-06 | 目标名称默认取值 | 浏览后取 `app_catalog` 的 `label`；无则取文件名去扩展名 |
| D-07 | R-016「失效标识」的实现方式 | 删除目标时**主动解除全部引用绑定** + 状态提示（避免残留死绑定）；另对残留 id 做防御性降级 |
| D-08 | 新增入口的哨兵 | `__launch__`，与既有 `__custom__` 并列；`actionLabel`/`isCurrent` 表达式天然兼容，仅需改 10 处 `onPicked` |
| D-09 | 目标注册表放置层级 | `settings.launch_targets`（全局共享，符合 R-005） |
| D-10 | macOS `.app` 启动方式 | `open -a <bundle_path> --args ...`（LaunchServices 语义），非 `.app` 时直接 `Popen` |
